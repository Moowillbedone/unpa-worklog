# 리뷰 · 제품등록 업무일지

언니의파우치 리뷰 검수 / 제품 등록 건바이건 정산 기록.
리뷰 **건당 500원**, 제품 등록 **건당 600원**.

## 파일

| 파일 | 설명 |
|---|---|
| `index.html` | 앱 본체. **기록이 들어있지 않습니다** |
| `data/log.json` | 실제 기록 (2026-01 ~ 2026-09) |
| `worklog-local.html` | 기록이 들어있는 단일 파일. 더블클릭하면 바로 열림 |
| `.vercelignore` | 배포에서 `data/` 를 제외 |

## 쓰는 방법 두 가지

**① 그냥 파일로 쓰기 (설정 없음)**
`worklog-local.html` 더블클릭 → 끝. 인터넷 없이도 동작하고, 입력한 값은 그 브라우저에 저장됩니다.

**② 주소로 쓰기 (다른 계정·다른 기기에서 접속)**
아래 배포를 한 번 해두면 어느 계정에서든 주소로 들어와 쓸 수 있습니다.

### 배포 (Vercel · 5분, 클릭만)

1. [vercel.com](https://vercel.com) 로그인 → **Add New → Project**
2. 이 저장소 선택 → **Import**
3. 설정 그대로 두고 **Deploy** → 1분 뒤 주소 발급

저장소가 비공개여도 배포됩니다. 코드를 수정해 push 하면 자동으로 다시 배포됩니다.

### 처음 접속했을 때

배포 주소로 들어가면 `data/log.json` 을 읽어 기록이 바로 뜹니다. 별도 설정이 필요 없습니다.
이후 입력한 값은 그 브라우저에 저장되고, **[내보내기]** 로 백업해 저장소에 반영합니다.

## 기록 저장 방식

입력은 즉시 **브라우저(localStorage)** 에 저장됩니다. Supabase에 로그인한 경우 업무일지 월별 데이터가 서버로 동기화됩니다. 계정별 저장소는 분리되며, 기존 비로그인 기록은 내보내기 → 로그인 → 가져오기로 명시적으로 이전합니다. 검수 상세 기록은 브라우저/JSON 보관이며 Supabase에 동기화하지 않습니다.

- **[내보내기]** — 백업 JSON 내려받기 → `data/log.json` 에 덮어쓰고 커밋하면 저장소에 남습니다
- **[가져오기]** — 백업 JSON 불러오기 (기기를 바꿨을 때)

브라우저 저장공간을 비우면 기록이 지워지므로, **가끔 [내보내기]로 저장소에 백업**해 두시는 걸 권합니다.

## CMS 바로가기

날짜를 고르면 검수 목록 주소를 만들어 줍니다.

```
https://cms.unpa.me/review/list/all?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD&beforeApproval=true
```

업무일지의 날짜 링크는 주소만 만듭니다. 별도 `tools.html`의 **리뷰 검수 콘솔**은 선택·최종 확인 후 CMS 승인, 수정요청, 미노출을 실제 실행합니다. 상품/브랜드 등록은 사람이 CMS에서 직접 합니다.

## 검수 콘솔 안전 기준

- 스캔은 GET 전용입니다. 브랜드 상품 목록 전체를 조회하고 연결 ID·제품 이미지 로드·본문·첨부 이미지를 확인합니다. 실패/불완전 조회는 보류합니다.
- 제품명+검증된 옵션은 매칭합니다. 단어 누락·에디션 차이는 후보로 제안하며 사람이 CMS 상세를 대조해 선택합니다. 검색 결과가 없더라도 새 등록 전에 직접 확인하세요.
- 사진 해상도는 직접촬영/도용/발색샷의 증거가 아닙니다. 그리드는 미선택으로 열리며 각 건의 사진·본문 일치 및 발색샷을 확인한 뒤 선택합니다. 유료 AI API는 사용하지 않습니다.
- 실행 전 상세 재조회, 템플릿 미리보기, 액션별 상한을 적용합니다. 전송 전에 실행 기록을 저장하며 응답 유실 건은 재실행을 차단합니다. 이런 건은 CMS 상세에서 처리 여부를 확인하고 기록 JSON과 대조하세요.
- 업무일지 반영은 출처 검증 메시지로 기록을 전달하고 사용자가 확인합니다. 리뷰 ID 중복을 제외합니다. 브라우저 저장소를 지우거나 기기를 바꾸면 CMS 실행 기록은 공유되지 않으므로 JSON 백업이 필요합니다.
- `cms-apply.js`, `cms-products.js`의 과거 고정 대상 도구는 실행을 중단했습니다. 콘솔을 사용하세요.

## 로컬 개발 / 복구

`npm test`로 네트워크 없는 회귀 테스트를 실행합니다. `npm run build`는 현재 `index.html`, `worklog-core.js`, `data/log.json`과 기존 Chart 번들로 `worklog-local.html`을 재생성합니다. 로컬 HTML을 직접 수정하지 마세요.

이번 개선의 복구 기준은 `c409ce16b577351b389c1ba20fcb7bbefe284555`입니다. `ROLLBACK.md`에 비파괴 복구 방법과 운영 검증 절차가 있습니다. 로컬 변경만으로 GitHub Pages 운영 버전이 바뀌지는 않습니다.

## 공개 범위

이 저장소는 현재 **공개(public)** 입니다. `data/log.json` 과 커밋 이력에 실제 수입 기록이
들어 있으므로, 주소를 아는 사람은 누구나 열람할 수 있습니다.

비공개로 바꾸려면 **Settings → Danger Zone → Change visibility → Private**.
비공개 저장소도 Vercel 무료(Hobby) 플랜에서 정상적으로 자동 배포됩니다.
다만 **배포된 주소 자체는 비공개 저장소여도 여전히 공개**이므로,
그때는 `.vercelignore` 의 `data/` 주석을 해제해야 실제로 가려집니다.
